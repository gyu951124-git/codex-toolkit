# 지식 문서 작성 규칙

생성하거나 문서 형식을 정비할 때 읽는다. 기존 지식베이스에 쓸 만한 구조가 있으면 유지하면서 아래 정보만 보완한다. 고정된 문서 수나 표 사용을 요구하지 않는다.

## 색인

기본 색인은 출력 루트의 `README.md`다. 기존 색인이 있으면 그 파일을 사용한다.

- 분석 대상과 목적, 원본 루트 별칭, 조사한 범위와 제외 범위를 기록한다.
- 주제 문서로 가는 링크와 한 줄 설명을 제공한다. 대형 프로젝트는 기능·모듈별로 나눈다.
- 문서별 상태를 `확인됨`, `부분 조사`, `재확인 필요`로 구분한다. 확인됨은 기록한 범위에 한정되며 전체 시스템의 정확성 보장이 아니다.
- 해결되지 않은 질문과 문서·코드 간 불일치를 찾을 위치를 연결한다.
- 조사 기준은 문서별로 기록한다. 색인의 변경 날짜를 전체 문서의 재확인 날짜로 해석하지 않도록 한다.

## 주제 선택

다음은 필요에 따라 나누는 주제다. 이름은 예시이며 기존 프로젝트 관례를 우선한다.

- `OVERVIEW.md`: 프로젝트 목적, 구성 요소, 기술 스택, 실행 진입점과 구성 관계.
- `DOMAIN.md`: 업무 용어, 핵심 개념, 상태·규칙, 개념 간 관계와 해당 구현 위치.
- `FLOWS.md`: 주요 기능별 시작 조건, 처리 순서, 분기·오류·부수 효과와 관련 코드.
- `DATA.md`: 핵심 엔티티·테이블·파일 형식, 데이터 관계, 읽기·쓰기 주체와 변환.
- `INTEGRATIONS.md`: 외부 연동의 역할, 호출 위치, 인증 방식과 코드에 확인되는 실패 처리.
- `CONVENTIONS.md`: 대표 코드에서 확인한 구현·오류 처리·테스트 관례와 설정 근거.
- `OPEN-QUESTIONS.md`: 업무 의도 질문, 충돌하는 설명, 자료 부족과 확인할 위치.

아키텍처·모듈 지도는 개요에 담거나 필요할 때 별도 문서로 나눈다. 도메인 개념이 없는 유틸리티에는 도메인 문서를 강제하지 않는다. 빈 주제 파일을 미리 생성하지 않는다.

## 각 문서의 조사 기준

문서 상단이나 하단에 다음을 기록한다.

- 조사한 원본 별칭과 기능·모듈 범위.
- 실제 확인 날짜와 상태.
- Git이 있으면 기준 커밋, 관련 작업 트리 변경 여부와 영향 경로. 저장소 전체가 dirty인지와 조사한 파일이 dirty인지 구분한다.
- Git이 없으면 확인한 파일·식별자와 날짜를 기록하고 변경 기준이 없음을 밝힌다.
- 조사하지 않은 부분, 실행하지 않아 확인되지 않은 동작과 필요한 추가 자료.

부분 갱신 문서에는 이번에 재확인한 절과 범위를 남긴다. 이전 범위까지 확인하지 않았다면 문서 전체를 새 기준으로 덮어 표시하지 않는다. 동일 파일을 다른 작업자가 수정한 정황이 있으면 저장 전 해당 근거를 다시 확인하거나 불확실성을 남긴다.

## 지식 항목

항목마다 사람이 읽기 쉬운 제목과 다음 내용을 담는다. 짧은 항목은 문단과 목록으로 표현한다.

1. **설명:** 어떤 기능·개념·관계인지, 관찰된 조건과 동작.
2. **근거:** 원본 별칭, 상대 경로와 함수·타입·SQL 객체·설정 키. 근거가 여러 파일에 걸치면 중요한 연결을 함께 기록.
3. **관련 지식:** 연결되는 기능·데이터·모듈과 해당 문서 링크.
4. **확실성:** 코드 확인 / 문서 명시 / 추정 / 미확인. 혼합된 항목은 문장별로 구분.
5. **남은 질문:** 코드만으로 알 수 없는 업무 의도와 추가로 필요한 자료가 있을 때 기록.

예를 들어 상태 상수 `CLOSED`를 발견했다고 해서 업무상 취소·완료의 의미를 확정하지 않는다. 읽기·쓰기 위치, 상태 전이와 관련 문서에서 확인한 의미를 기록하고 남은 의미는 질문으로 남긴다.

기존 문서를 근거로 인용할 때는 원본 문서 경로를 붙인다. 생성된 지식 문서끼리의 링크는 탐색용이며 구현 사실의 원본 근거를 대체하지 않는다. 외부 원본 경로는 색인의 별칭으로 연결하고 개인 PC 절대 경로를 각 항목에 반복하지 않는다.

## 정적 확인과 인수인계

- 작성·수정한 항목의 근거 경로와 식별자가 실제로 존재하는지 확인한다.
- 주요 흐름이 관련 코드의 호출·분기·데이터 접근과 일치하는지 확인한다.
- 수정한 지식과 연결된 문서 간 설명·링크가 충돌하지 않는지 확인한다.
- 확인할 수 없는 내용은 지우거나 사실로 바꾸지 말고 상태와 이유를 남긴다.
- 결과 보고에는 생성·갱신·무변경 여부, 문서 목록, 확인 범위, 남은 사항을 남긴다. 설치·실행·테스트를 수행한 것으로 표현하지 않는다.
