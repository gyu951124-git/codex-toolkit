# 코드베이스 지식베이스 생성·갱신

사용자가 지정한 분석 대상 자원에서 이후 재사용할 프로젝트 지식을 만든다. 실제 코드를 근거로 구조·업무 개념·기능 흐름·데이터 관계를 연결한다. 질의응답 기능은 이 skill의 범위 밖이다.

## 작업 계약과 경로

- 대상 원본 루트, 조사 범위, 생성·갱신 목적, 출력 위치를 먼저 확인한다. 사용자가 명시한 범위를 전체 저장소 조사로 확대하지 않는다.
- 지정된 출력 위치나 기존 지식베이스 위치를 우선한다. 프로젝트가 명확하고 별도 위치가 없으면 해당 프로젝트의 `docs/codebase/`를 사용한다. toolkit에 분석 대상 프로젝트의 지식을 저장하지 않는다.
- 원본 루트와 출력 루트는 별도로 기록한다. 여러 저장소는 `backend`, `batch` 같은 별칭으로 구분하고 각 별칭의 루트와 기준을 색인에 남긴다. 근거 경로는 해당 원본 루트 기준 상대 경로로 쓴다.
- 기존 지식베이스가 둘 이상이고 선택할 근거가 없으면 확인한다. 지식베이스 문서와 출력용 임시 파일은 소스 조사에서 제외한다.
- 코드·설정·기존 원본 문서를 변경하지 않는다. 쓰기는 지정된 지식베이스 범위에 한정한다. 출력 경로가 원본 파일과 충돌하면 다른 위치가 정해질 때까지 덮어쓰지 않는다.

## 생성

1. 기존 지식베이스 유무를 확인한다. 있으면 중복 생성 대신 갱신 절차를 적용한다.
2. `rg --files`, 설정 파일과 진입점 등으로 대상의 윤곽을 파악한다. `.gitignore`를 존중하고 의존성·빌드 산출물·캐시·바이너리는 기본 제외한다. 중요한 분석 대상 자원이 제외된 경우 해당 경로만 명시적으로 조사한다.
3. README·설계서·스키마·테스트와 실제 코드를 비교한다. 기존 문서의 의도와 구현 사실이 다르면 각각의 근거와 차이를 기록한다. 기술 스택을 가정하지 말고 프로젝트 파일에서 확인한다.
4. 대상 기능을 진입점 → 처리 → 업무 규칙 → 데이터·외부 연동 → 결과 순으로 추적한다. 시스템의 배치, SQL·프로시저, 화면 이벤트, 파일 교환, 설정 기반 호출도 실제 사용 경로를 확인한다.
5. [지식 문서 작성 규칙](references/knowledge-format.md)에 따라 색인과 필요한 주제 문서를 작성한다. 작은 범위는 한 문서에 통합할 수 있으며 빈 문서를 채우기 위해 조사 범위를 늘리지 않는다.
6. 작성한 설명의 근거와 내부 링크를 정적으로 확인하고 범위·누락·미확인 사항을 보고한다.

대형 저장소는 먼저 전체 윤곽과 우선 조사 영역을 기록하고 해당 영역을 깊게 조사한다. 대표 코드만 표본 조사했으면 그 범위를 명시한다. 접근 제한·자료 부족을 이유로 임의의 구조나 업무 규칙을 만들어 채우지 않는다.

## 갱신

1. 색인과 관련 문서에서 각 문서의 조사 기준·근거·미확인 사항을 읽는다. 문서의 설명은 탐색 단서이며 현재 원본을 확인한 뒤 유지한다.
2. 변경 기준이 지정되면 해당 기준을 사용한다. Git 기준이 있으면 커밋 간 변경과 현재 작업 트리의 staged·unstaged·관련 untracked 파일을 함께 확인한다. Git이 없거나 기록된 기준을 찾을 수 없으면 관련 원본과 문서를 직접 비교하고 비교 한계를 남긴다. 커밋이 같아도 작업 트리가 같다고 가정하지 않는다.
3. 변경 파일을 근거로 사용하는 문서, 호출자·피호출자, 공용 타입·스키마·설정과 연결된 흐름을 확인한다. rename·삭제는 코드의 대체 경로와 문서 간 링크까지 확인한다. 파일명 목록만으로 영향이 없다고 판단하지 않는다.
4. 영향을 받는 설명과 근거를 수정하고 재확인한 범위의 조사 기준만 갱신한다. 일부 문서의 재확인을 전체 지식베이스 갱신으로 표시하지 않는다. 영향은 있으나 확인하지 못한 문서는 `재확인 필요`로 표시한다.
5. 오래된 설명을 조용히 현재 사실로 남기지 않는다. 삭제된 기능은 현재 제공되지 않음을 명시하고, 기존 역사 설명·사용자 주석은 의미를 보존한다. 기존 문서 전체 삭제나 구조 전면 개편이 필요하면 주 agent에게 반환한다.
6. 실질적 변경이 없으면 불필요하게 문서와 날짜를 다시 쓰지 않고 확인 범위와 무변경 결과를 보고한다.

## 근거와 종료 기준

- 주요 설명마다 원본 경로와 함수·타입·SQL 객체·설정 키 등 재탐색 가능한 식별자를 붙인다. 줄 번호는 보조 정보로만 사용한다.
- 코드상 사실, 문서에 명시된 업무 의도, 추정과 미확인을 구분한다. 이름만 보고 업무 의미를 확정하지 않는다. 테스트는 기대 동작의 단서이며 실행 성공이나 운영 동작의 증거는 아니다.
- TODO·큰 파일·잦은 변경은 조사 단서다. 실제 문제로 기록하려면 발생 조건과 영향을 확인한다. 문서 갱신 중 원본의 개선·리팩터링을 수행하지 않는다.
- 비밀값·개인정보·실제 고객 데이터를 문서에 복사하지 않는다. 환경변수 이름, 설정 위치와 역할만 기록한다. DB·API·운영 시스템에 접속하거나 코드를 실행해 추가 자료를 얻지 않는다.
- 작성·수정한 문서의 근거 경로와 식별자, 문서 링크, 상충하는 설명을 확인한다. 자료가 부족한 질문은 목록으로 남기고 종료한다. 새 근거 없이 재조사를 반복하지 않는다.
- 완료 보고에는 조사 범위·기준, 변경 문서, 주요 발견, 미확인 사항과 미수행 실행 검증을 포함한다. 범위가 부분적이면 부분 완료로 보고한다.
