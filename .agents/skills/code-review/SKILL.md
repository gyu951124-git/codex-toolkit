# 코드 리뷰

## 검토 범위

요구사항, 검토 파일, 비교 기준과 실제 검증 결과를 확인한다. 구현자의 요약뿐 아니라 실제 파일·차이와 관련 호출부를 읽는다. 비교 기준이 없으면 확인 가능한 범위와 한계를 밝힌다.

리뷰는 읽기와 발견 사항 보고가 기본이다. 리뷰 요청만으로 코드 수정이나 agent 위임을 수행하지 않는다. 실행 검증이 필요하면 프로젝트의 `verification` 지침과 허용 범위를 따른다.

## 검토 기준

먼저 요구사항 누락과 범위 초과를 확인하고, 그다음 실제 결함과 불필요한 복잡성을 검토한다. 같은 reviewer가 두 관점을 확인하며 이를 위해 별도 agent를 추가로 요구하지 않는다.

- 요구사항 충족: 기대 행동, 빠진 조건, 승인 범위를 넘는 변경과 문서·설정의 불일치를 확인한다.
- 코드 품질: 실제 실행 경로의 오류와 회귀, 변경과 관련된 데이터·보안·동시성 문제, 근거 없는 복잡성을 확인한다.
- 발견 사항은 발생 가능한 조건과 구체적인 영향을 제시한다. 변경과 무관한 기존 문제나 취향에 따른 개선을 필수 수정으로 분류하지 않는다.
- 테스트 미수행은 검증 한계로 표시한다. 그 사실만으로 버그를 단정하지 않는다.

## 결과 보고

결함마다 심각도, 파일·행 또는 심볼, 발생 조건, 영향, 근거와 수정 방향을 적는다. 심각도는 즉시 해결할 중대한 문제, 주요 동작 오류·회귀, 제한적인 영향으로 구분한다. 선택적 개선과 확인이 필요한 추정은 별도로 표시한다.

결함이 없으면 검토 범위에서 발견하지 못했다고 표현한다. 실제 동작이나 무결함을 보장하지 않는다. 검토 범위와 수행한 확인, 미검증 사항을 함께 보고한다.

주 agent가 발견 사항을 요구사항과 대조해 수정 여부를 판단한다. 직접 검토한 경우 자체 검토임을 밝힌다. Superpowers 작업의 반복 제한은 superpowers-workflow를 기준으로 주 agent가 기록하며, reviewer는 전달받은 제한과 현재 횟수를 따른다. 남은 중요한 결함은 미해결로 보고한다. 다른 절차에는 이 반복 제한을 자동 적용하지 않는다.
