# 개발 작업 조율

현재 대화의 주 agent가 조율한다. 프로젝트의 AGENTS.md에서 논의와 실행을 구분하고, 명확히 요청된 범위는 반복 승인 없이 진행한다.

## 진입 시 개발 절차 확인

조사 문서·계획·작업 목록을 만들기 전에 프로젝트 AGENTS.md에서 선택한 절차와 요청 단계를 확인한다. 이 skill은 Superpowers로 선택한 범위에 적용하며 사용자가 이름을 직접 언급할 필요는 없다.

구현·수정은 기존 논의와 확정된 요구사항을 사용한다. 별도 논의가 없어도 핵심 동작과 범위가 명확하면 진행한다. 이를 정할 수 없으면 프로젝트 루트의 .agents/skills/requirements-clarification/SKILL.md에 따라 질문·계획에서 필요한 부분만 구체화한 뒤 이어간다. 모든 요청에 깊은 문답을 추가하거나 확정된 설계를 다시 논의하지 않는다.

선택 경계가 불명확하거나 절차 전환이 필요하면 프로젝트 루트의 [.codex/references/workflow-selection.md](../../../.codex/references/workflow-selection.md)에서 해당 항목을 읽는다. Spec Kit으로 선택한 범위는 주 agent가 전용 조율 agent로 처리하고, 직접 처리할 국소 수정은 공통 품질 skill만 사용한다.

위임받은 agent에게 잘못 전달된 경우 조율을 시작하지 않고 계약·진행 상태·충돌 근거를 주 agent에게 반환한다. 다른 agent를 생성하거나 전달된 절차를 바꾸지 않는다.

## 조사와 계획

관련 코드와 설정, 기존 결정 및 진행 기록이 있으면 확인한다. 파일 수보다 의존 관계와 결정 사항을 놓칠 가능성을 기준으로 기록 수준을 선택한다.

구현 전에 기대 동작, 변경 범위와 완료 확인 방법을 정한다. 여러 작업이 연결되면 의존 관계와 실행 순서를 추가한다. 기록은 작업 규모에 따라 대화나 문서에 남기며, 별도 파일이나 정해진 양식을 필수로 요구하지 않는다.

- 작은 변경은 최소 계획을 대화에 남기고 별도 문서 없이 진행한다.
- 여러 작업이 연결되면 변경 대상, 순서, 완료 기준을 대화나 짧은 계획 문서 하나에 기록한다.
- 조사 근거·대안이 많거나 긴 작업을 재개해야 하면 필요에 따라 Research.md와 Plan.md로 나눈다. 사용자 지정 경로와 문서 생성 제한을 따른다.

문서 작성 자체를 승인 대기 단계로 만들지 않는다. 결과를 크게 바꾸는 선택이나 요청 범위 확대만 확인한다. 완료 작업을 재실행하지 않도록 실제 파일과 기록을 대조한다.

구현 중 새 근거로 기존 가정이나 계획이 달라지면 변경 이유, 영향을 받는 결정과 남은 작업을 기존 기록에 갱신한다. 승인된 범위 안의 구현 선택은 직접 조정하고, 요구 동작·완료 조건·작업 범위가 바뀌거나 결과를 크게 바꾸는 선택이면 필요한 결정을 사용자에게 확인한다. 영향받는 위임 계약도 갱신해 담당자에게 전달하고, 이미 완료한 작업은 새 근거로 재확인이 필요한 부분만 다시 확인한다. 계획 변경만으로 개발 절차를 전환하거나 반복 횟수를 초기화하지 않는다.

## 실행과 위임

기본은 주 agent가 직접 구현하고 검토한다. 사용자가 위임을 요청하거나 적용 지침이 명시적으로 허용하고 도구가 지원할 때만 agent를 사용한다. 이 skill 선택 자체를 위임 승인으로 해석하지 않는다.

위임이 허용된 범위에서는 복잡한 변경의 독립 검토, 담당 파일과 의존 관계를 분리할 수 있는 독립 구현 작업, 조사량이 많아 맥락을 분리할 필요가 있는 작업에 위임을 고려한다. 전달·조율 비용과 기대 이점을 비교하고 짧은 국소 작업은 직접 처리한다. 조사 목적이라면 읽기 범위와 반환할 근거를 정하고, 실제 지원되는 역할에 맡긴다. 이 판단 기준은 새로운 위임이나 병렬 실행 권한을 부여하지 않는다.

위임할 때 [delegation.md](references/delegation.md)를 읽는다. sp_implementer와 sp_reviewer의 실제 역할 노출을 확인한다. 미등록이면 직접 처리하거나 허용된 기본 역할로 대체하고 그 사실을 알린다. 모델과 권한을 임의로 확대하지 않는다.

위임이 허용되어 사용하는 경우 구현 담당 1명, 리뷰 담당 1명을 기준으로 한다. 의존 작업은 순차 진행하며 추가 병렬 구현이 허용된 경우 독립 파일 소유권을 나눈다.

## 단계 연결

프로젝트 루트 기준으로 필요한 skill을 읽는다. 구현 시작 전에 TDD 적용 여부를 확인한다. 사용자 요청 또는 승인된 작업 절차·계획에서 TDD나 테스트 우선 구현을 명시한 경우 .agents/skills/test-driven-development/SKILL.md의 순서에 따라 구현과 검증을 연결한다. 일반적인 테스트 작성 요구만으로 TDD를 강제하지 않는다.

1. 구현: .agents/skills/implementation/SKILL.md.
2. 결과 확인: .agents/skills/verification/SKILL.md. 변경에 맞는 검증을 선택하고 사용자 제한을 따른다.
3. 실제 변경 리뷰: .agents/skills/code-review/SKILL.md. 직접 처리하면 자체 검토임을, 위임하면 독립 리뷰임을 밝힌다.

Superpowers의 반복 제한은 이 문서를 기준으로 한다. 초기 리뷰 이후 수정·재검토는 작업당 최대 2회다. 주 agent가 초기 리뷰와 이후 수정·재검토 회차를 구분해 기록하고, 재개·위임 시 현재 횟수와 제한을 전달한다. 한 차례 수정 후 재검토를 한 회로 센다. 남은 중요한 결함은 미완료로 보고하며 추가 반복에 필요한 결정과 이유를 알린다. 작업 ID 변경이나 새 agent 생성으로 횟수를 초기화하지 않는다. 관련 없는 독립 작업은 계속할 수 있다.

## 전체 완료 확인

주 agent는 작업별 결과를 취합한 뒤 전체 완료 조건, 작업 간 인터페이스와 누락된 연결을 실제 변경에 대조한다. 개별 작업의 성공 보고만으로 전체 기능 완료를 판단하지 않는다. 기존 검증으로 확인되지 않은 연결 부분에 필요한 검증을 선택하고 사용자 실행 제한을 따른다. 변경이나 새 근거가 없으면 이미 통과한 검증을 반복하지 않는다.

구현 완료, 실제 검증 결과와 미해결·미검증 사항을 구분해 보고하고 진행 기록이 있으면 갱신한다. 자동 commit/push/merge, 배포, worktree 생성과 기존 코드 삭제를 필수 단계로 삼지 않는다.
