# 테스트 기반 개발

## 적용 조건

사용자 요청 또는 승인된 작업 절차·계획에서 TDD나 테스트 우선 구현을 명시했는지와 그 근거를 확인한다. 일반적인 테스트 작성 요구만으로 TDD를 강제하지 않는다. 테스트 작성·실행 제한을 따르며 테스트 금지이면 실행하지 않는다. 작성만 허용되면 미실행임을 밝히고 TDD 완료라고 표현하지 않는다.

일반 검증 범위와 테스트 품질은 프로젝트 루트의 .agents/skills/verification/SKILL.md에 따른다. 테스트 환경이 없으면 원인과 미수행 단계를 알리며 설치를 임의로 수행하지 않는다.

## RED → GREEN → REFACTOR

1. RED: 요구된 행동이나 버그 재현 조건을 테스트로 작성하고 실행해 해당 행동 부재로 실패하는지 확인한다. 구문·환경 오류는 유효한 RED가 아니다. 이미 통과하면 요구사항과 테스트가 검증하는 조건을 확인한다.
2. GREEN: 테스트를 통과하는 최소 구현을 작성하고 같은 테스트의 성공을 확인한다. 구현 기준은 .agents/skills/implementation/SKILL.md를 따른다.
3. REFACTOR: 동작을 유지하며 필요한 구조를 정리하고 관련 테스트를 다시 실행한다. 새 기능을 섞지 않는다.

기존 구현이나 사용자 변경을 순서를 맞춘다는 이유로 삭제하지 않는다. 기존 구현에 테스트를 추가했다면 실제 수행 순서를 그대로 보고하고 RED 증거를 사후에 만들어내지 않는다.

## 증거

실행 명령, 의도한 실패 이유와 실제 실패 결과, 성공 결과와 미실행 회귀 범위를 기록한다. 실행할 수 없으면 그 단계는 미검증이다. 로그는 필요한 부분만 요약한다. 검증된 범위를 넘는 성공을 주장하지 않는다.
