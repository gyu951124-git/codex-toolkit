# 개발 절차 선택 세부 규칙

기본 선택은 프로젝트 루트의 `AGENTS.md`를 따른다. 주 agent는 선택 경계가 불명확할 때 「선택 경계」, 위임할 때 「위임 계약」, 절차를 전환할 때 「전환과 인계」를 읽는다. 위임받은 agent는 계약 확인이나 충돌 해결에 필요한 항목만 읽고 절차를 재선택하지 않는다.

## 선택 경계

- Spec Kit 채택 여부는 프로젝트 지침, 사용자의 결정과 해당 작업의 기존 명세·진행 기록으로 확인한다. `.specify/`나 명세 파일만 남아 있다는 이유로 채택을 추정하지 않는다. 채택 여부가 불명확하고 관련 요구사항을 변경해야 하면 필요한 선택을 확인한다. 관련 없는 국소 수정은 그 이유만으로 중단하지 않는다.
- 직접 처리할 수 있는 국소 수정은 오타·문구·포맷 변경, 동작을 유지하는 작은 내부 수정, 이미 명세된 동작으로 복구하는 버그 수정이다. 작은 버그여도 기대 동작이 미정이거나 인터페이스·데이터 계약을 바꾸면 요구사항 변경으로 판단한다. 파일 수 대신 설계 결정, 의존 작업과 사용자에게 보이는 동작 변화를 확인한다.
- 프로젝트가 모든 변경에 명세 절차를 요구하면 국소 수정도 해당 규칙을 확인한다. 사용자 지정 방식과 충돌하면 차이를 설명하고 필요한 결정을 확인한다. 사용자가 작은 수정에 Spec Kit을 지정하면 설치된 절차에서 해당 범위만 수행하고 새 기능 문서 전체를 임의로 재생성하지 않는다.
- 기존 방식으로 Spec Kit 관련 코드를 수정하더라도 관련 명세·원칙·완료 조건과의 일치와 문서 영향을 확인한다. 승인된 쓰기 범위에서 영향 문서를 갱신하거나 남은 갱신을 보고한다. 문서 영향만으로 전체 명세 절차를 재시작하지 않는다.
- 현재 코드를 분석해 지식베이스 문서를 만드는 요청은 `codebase_knowledge_builder`의 업무다. 지식베이스 생성 프로그램·뷰어·질의응답 기능의 구현은 개발 작업이다. 개발 중 지식 문서 생성이 별도 요청되면 주 agent가 문서 작업의 범위를 분리하고 전체 개발 절차를 유지한다.

## 위임 계약

주 agent는 전체 대화 대신 필요한 맥락과 실제 경로를 전달한다.

- 프로젝트 루트, 목적, 대상 기능·작업 ID와 요청 단계.
- 선택된 절차(Spec Kit / Superpowers / 직접 처리)와 기준 명세·계획·작업 목록, 기존 결정과 완료 조건.
- 적용 지침, 담당 파일·모듈, 의존 작업, 공유 인터페이스와 제외 범위.
- 허용된 쓰기·실행 범위, 테스트 작성·실행 및 설치 제한.
- 사용자 요청 또는 승인된 절차·계획에 명시된 TDD 여부와 그 근거. 일반 테스트 작성 요구를 TDD로 확대하지 않는다.
- 필요한 skill·참조 경로, 완료·미완료 작업, 실제 검증 결과, 반복 제한과 현재 횟수, 반환할 결과.

공유 설정·생성 파일·계획·진행 기록에도 쓰기 담당을 정한다. 같은 파일의 동시 쓰기를 피하고 담당 밖 변경은 주 agent에게 반환한다. 사용자와 다른 작업자의 변경을 보존한다.

Spec Kit의 구현·리뷰 위임은 Superpowers 전체 절차를 시작하지 않는다. `speckit_coordinator`는 필요한 위임을 주 agent에게 반환하며 직접 agent를 생성하지 않는다. Superpowers의 반복 제한을 다른 절차에 자동 적용하지 않는다.

## 전환과 인계

전환은 사용자 결정이나 명확한 범위 변경에 따라 주 agent가 조정한다. 기존 변경, 기준 산출물과 결정, 완료·미완료 작업 및 검증 결과를 인계하고 현재 조율을 끝낸 뒤 다음 절차를 시작한다.

Spec Kit에서는 공식 산출물, Superpowers에서는 기존 계획·기록을 기준으로 삼는다. 같은 범위의 계획·작업 목록을 중복 생성하거나 완료 작업을 재실행하지 않는다. 담당 agent끼리 서로 작업을 되돌려 보내지 않는다.

전용 agent나 필요한 지침이 없으면 누락과 가능한 다음 행동을 알린다. 대체 역할이 허용되는지는 선택된 절차의 지침과 기존 승인 범위에서 확인하며 실제 대체 사실을 보고한다. 설치·초기화나 새로운 위임 권한을 전환에 포함하지 않는다.
